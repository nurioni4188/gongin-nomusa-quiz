## 문제의 원인과 반영 작업
- 1차 기본앱은 2008~2021년 전체를 연도로 판정하는 채점 차단 로직 때문에 홈 타일·풀이 화면·복습화면에 같은 `HOLD` 문구가 반복돼 있었다.
- 정답조회화면도 원문연결 900건의 증거 차이를 무시하고 검증 칸 전체를 `HOLD`로 출력했다.
- `study-hub/first-v32-proof-status.js`: 실제 공식 출처에 연결된 문항의 PDF 문자층·OCR 후보·문항번호 이미지 확인과 정답표 자동대조를 구분한다.
- `study-hub/first-legacy-answers.html`: 원문/정답의 두 단계를 텍스트로 보여주고 모바일 카드형으로 출력하며 전체 채점승인 대기 경고는 페이지 상단 한 번만 안내.
- `study-hub/index.html`과 `study-hub/app.js`: 중복 전역 안내 배너 제거, 1차 단일 검증 페이지 링크.
- `index.html`: 홈 연도별 타일 `HOLD` 반복을 채점 전 `선택` 표시로, 풀이 중 같은 HOLD 경고 중복을 하나로 바꿈. 기존 저장키/점수 차단 기능 보존.

## 중요한 HOLD
- 3,400개 정답 후보 승인 0건. 원본·정답값을 임의로 고치거나 미승인 채점을 활성화하지 않는다.
- 44개 PDF 연동 HOLD 전부를 해소한 것은 아님. V62 3개·V71 14개는 이전부터 제한된 별도 시각확인이 있었으나 원장 최종승인 전.
- `main`·Production·기존 Preview·원본 PDF/문항ID/저장키 불변; 신 Preview는 별도 성공검증 뒤에만.

## 구형 V6 회귀검증과 현재 소스의 차이
- 예전 V6.8 혼합 테스트는 2차 카탈로그 309개(기존 215+추가 94)를 고정 기대하여, 현재 377개 학습단위(기존 283+추가 94)를 확인하면 1차 화면과 무관하게 실패한다. 현재 검증된 328개 2차 답안과 377개 학습단위는 **집계 기준이 다르다**. 숫자를 바꿔 임의 PASS 처리하지 않는다.
- V32는 구형 테스트에 선택적 `--first-only`(1차/과거 PDF 6건) 기능을 추가하되, 기본 기존 동작은 유지한다. 2차/허브는 현재 실제 소스에 맞는 `nomusa-canonical-shared-browser-gate.py`를 재사용한다.
